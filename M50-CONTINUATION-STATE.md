## Root-cause corrections completed through Checkpoint 03

1. **Viewer mutation authority mismatch:** historical workspace RPCs and Storage insert policy accepted Board `view` access even though the UI described viewer membership as read-only. M50 aligns update, property, upload, and delete mutation authority to Board `edit` access while preserving `view` for reads/previews/downloads.
2. **Metadata-first attachment deletion could orphan private Storage objects:** the client previously deleted metadata before Storage cleanup. M50 performs Storage deletion first and finalizes metadata second; failed Storage deletion leaves metadata visible and retryable, while failed metadata finalization remains observable and idempotent.
3. **Ambiguous upload-registration responses could destroy committed files:** an RPC response loss after successful metadata commit previously looked indistinguishable from a failed registration. M50 retries idempotently, reloads the authoritative workspace, and only rolls back the Storage object after proving registration is absent.
4. **Attachment registration trusted the client path without proving object ownership:** M50 verifies that the exact private Storage object exists under the Board/item path and is owned by `auth.uid()` before metadata registration.
5. **Permanent item/Board deletion could bypass unregistered object cleanup:** M50 fails closed when either attachment metadata or matching pending Storage objects remain.
6. **Certified-predecessor provenance drift:** M50 no longer rewrites M49 repository source to `active-certified`; it pins the independently verified M49 certified commit, source-tree digest, hosted run, and certified-artifact digest while retaining M49's fail-closed source state.
7. **Production migration-history mismatch risk:** the isolated M50 deployment workspace now carries the exact applied M46 (`20260917142647`) and M47 (`20260919165239`) deployment migrations as history anchors before the new M50 (`20260922141400`) migration. It uses ordinary ordered `db push` rather than `--include-all`.
8. **Browser evidence cardinality drift:** the M50 browser authority now reports all five lifecycle scenarios: property/update persistence, normal file lifecycle, lost registration-response recovery, Storage-delete retry recovery, and viewer read-only behavior.
